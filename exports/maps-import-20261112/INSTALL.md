## Before installing: re-run the stage

The DBC baselines are read at stage time (current effective client files, and the live container's server DBCs).
Other work in progress (housing, CoA scaling, Manastorm) can change those. Re-run so the rows are merged onto
whatever is current; the run refuses duplicate IDs instead of overwriting:

```bash
python -I Tools/maps_import/stage_maps.py <scratch-dir> island scene morza risen
python -I Tools/maps_import/validate.py <scratch-dir>
```

(`<scratch-dir>`: any writable folder. Reads `G:\3.3.5a - Dev\Data` read-only and `D:\Sirus\_client`.)

## Install order (when you decide to)

1. **Client** (WoW closed): back up `Data`, copy the five `client/*.MPQ` into `Data`. Do not copy anything else.
2. **Server DBCs**: the four files in `server/dbc/` must replace the server's `Map`, `AreaTable`, `AreaTrigger`,
   `WorldSafeLocs`. The worldserver reads them from `/azerothcore/env/dist/data/dbc`. `AreaTable` is currently a
   bind mount from `modules/mod-fly-anywhere/data/patch/server/AreaTable.dbc`, so either point that mount at the merged
   file or copy the merged rows into that source file. The other three are plain files in the data volume; add compose
   `volumes:` lines like
   `./exports/maps-import-20261112/server/dbc/Map.dbc:/azerothcore/env/dist/data/dbc/Map.dbc:ro`.
   (Not done: compose files belong to the active deploy.)
3. **Server map data** (see "Terrain data" below). Without `.map` files the server has no ground or liquid data.
4. **SQL** (applied by hand: the image sets `AC_UPDATES_ENABLE_DATABASES=0`), against `acore_world`:
   `scenegaming_world.sql`, `risendepths_world.sql`, `morza_world.sql`, then `maps_game_tele.sql`.
   Each file deletes only the exact IDs it inserts, so it can be re-applied.
5. Restart the worldserver with the matched DBCs. Rollback: remove the five MPQs, restore server DBCs, run
   the uninstall deletes (ID ranges listed below).

## Terrain data for the server

`map_extractor`, `vmap4_extractor`, `vmap4_assembler` and `mmaps_generator` are in `src/tools/` but **not built**
on this machine (build with `-DTOOLS_BUILD=maps-only`; not done here, per "don't build"). Needed:

* Map 5000: already staged under `server/data` (shipped prebuilt by the Morza kit).
* Maps 1405, 1410, 1411, 1412, 1430: run `map_extractor` against the client `Data` **after** step 1 (so the new Map
  rows and ADTs are present). Copy only the new files into the data volume:
  `maps/` files whose name starts with `1405`, `1410`, `1411`, `1412`, `1430` (12 characters, `MMMMXXYY.map`). `vmaps`
  and `mmaps` for these are optional (pathing and line of sight); generate with `mmaps_generator <mapId>` if wanted.
